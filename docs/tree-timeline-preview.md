# 树状时间轴预览

这是独立于稳定版 0.5.0 的 0.6.0-preview.1。旧版程序、旧工程和经典渲染器保留。预览版可以打开旧工程，也可以把新版保存的工程交给旧版继续编辑。

## 主界面

条件树直接占用主时间轴：左侧分支从上到下排列，右侧是对应动作的参考片段。技能名和 E、Q 等标记同时出现在分支标题中，缩小参考轴也能识别动作。

- 上下拖动分支手柄，或点击上下箭头，调整原生优先顺序。
- 展开“全部满足”或“任一满足”，查看子条件。点选一个节点，就在时间轴上方修改目标角色、记录、比较方式、数值或取反。
- 条件素材可以拖进某个分组；点击素材会添加到当前选中的分组。
- 分支下方的增加分支按钮为同一动作增加另一种触发条件；它不会复制动作或建立一份新的执行记录。
- 左右拖动右侧片段只修改参考位置。普攻等可变动作可以调整长度，E、Q 释放片段继续沿用实测校准规则。
- “经典 / 树状新版”只切换界面，沿用同一份当前工程及撤销记录。

在手机上可点选条件素材和使用上下箭头；角色库、属性、缩放及动作入口沿用原移动布局。

## 原生执行规则

树状视图仅用于 JSON 的“条件与优先级”。TXT、JSON 步骤与计划模式继续使用经典时间轴，不会被自动转成条件策略。

原生运行器每次从优先级最小的条目开始检查，选择第一个成立的动作；该动作命令结束后，重新从顶部检查。树的上下顺序表示这个检查顺序。分组节点表示 `&&`、`||` 和取反，分组内部的子条件不是分先后执行的战斗动作。右侧位置是编排参考，不表示运行器承诺在某一毫秒执行。

`MorePriorities` 会将同一动作以另一组条件放入检查队列，所以可能在不同位置看到关联到同一动作的分支。未知的原生子表达式保持原文，点击后可明确编辑；打开或切换视图不改写表达式。同优先级保持原始声明顺序，直到用户明确重排。

多人策略先绑定当前玩家，再检查其私人动作和各端通用动作。调整私人分支不改另一端的动作、编号、声明顺序或条件。各端通用分支需切到“各端通用”后调整，它会影响所有玩家。

## 编号与兼容

原生 `Action.Index` 同时用于主优先级和执行记录身份，不能在调整顺序时随意重编号。预览版移动主触发时保留原 `Index`、`Name` 和声明顺序，将主表达式放入原生 `MorePriorities`，原主表达式设为 `false`。新的整数优先级只写入替代触发条目。原生执行器和 0.5.0 已经支持这种普通 JSON。

工程中的 `clips[].treePrimary` 只用于将这组兼容字段重新显示为一个主触发，不是运行器接口。经典视图可看到真实的 `false` 主条件和新增替代触发。编辑器仅在这两者仍与标记完全匹配时使用标记；手工改动原生条件后，以实际条件为准。

工程格式仍为 `betterbgi-combat-timeline` 版本 1，编辑器 API 仍为 1，编译器版本仍为 3、4、5、6。TXT、单人 JSON、多队伍及多人 JSON 沿用现有导入导出与网站集成契约，不添加私有网站接口。

## 两个版本并存

预览版 Electron 使用独立的应用名、应用标识和 `BetterGI Combat Editor Tree Preview` 用户目录，不覆盖稳定版目录。浏览器 `tree.html` 使用 `betterbgi.combat-timeline.tree-preview.v1` 保存草稿；首次打开可以读取旧草稿作为副本，后续写入预览草稿键。`index.html` 继续使用经典草稿键。

两个版本之间用保存的 `.combat-timeline.json` 或带工程元数据的战斗 JSON 交换文件。预览版不会将未实测动画时长标成准确数据，也没有增加对真实技能成功释放的反馈能力。
