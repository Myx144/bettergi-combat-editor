# BetterGI Combat Editor

面向 BetterGI TXT 与 JSON 战斗策略的可视化编辑器。

将角色拖入时间轴，再编排技能、普攻、等待、移动、冲刺及键鼠动作。TXT 与 JSON 分别编辑和导出；支持多人联机 JSON、多队伍合并 JSON、共享角色关系、角色兼容分支、跨角色插入、框选整体吸附、撤销重做和工程保存。桌面与移动端共用同一套编辑逻辑。

## 树状新版预览

`preview/tree-timeline` 分支提供 `0.6.0-preview.2`。稳定版仍为 `0.5.0`，原程序和工程可继续使用。预览版成品名为 `BetterGI-Combat-Editor-Tree-0.6.0-preview.2-win-x64.exe`，使用独立草稿目录，可以与稳定版并存。

预览版将 JSON 条件分支放入主时间轴：上面的分支先检查，条件通过后执行右边的动作；“全部满足 / 任一满足”可以展开，条件素材可以直接拖入分组。上下拖动分支或使用箭头调整检查顺序，左右拖动片段调整参考排轴。为同一动作添加另一种触发方式时，仍共用该动作的执行记录。

工具栏可随时切回经典时间轴。浏览器打开 `tree.html` 进入新版，`index.html` 默认进入经典版。TXT、JSON 步骤与计划模式保留经典时间轴；切换视图不会转换策略格式或修改工程。多人策略先选择玩家，再编辑本端和各端通用分支。

兼容处理、原生优先级和草稿隔离说明见 [树状时间轴预览](docs/tree-timeline-preview.md)。

## 直接运行

Windows 成品无需安装 Node.js、Python 或 BetterGI。

1. 下载 Windows x64 便携版，双击 `BetterGI-Combat-Editor-版本-win-x64.exe`。
2. 或解压 Windows ZIP，双击其中的 `BetterGI Combat Editor.exe`。
3. 工程保存为 `.combat-timeline.json`；运行策略按当前模式导出 `.txt` 或 `.json`，交给支持该格式的 BetterGI 任务入口使用。

浏览器版直接打开本仓库的 `index.html` 即可，也可以放到静态网站上。

`examples/raiden-team.project.json` 是可重新编辑的示例工程，`examples/raiden-team.combat.json` 是对应的战斗脚本。

`examples/raiden-team.txt` 展示 TXT 顺序命令，`examples/conditional-priority.combat.json` 展示低血量治疗优先及替代触发条件，可直接导入编辑。

片段属性的“编排触发条件”支持从素材库拖入条件，按“全部满足 / 任一满足”组合，配置目标角色、前置动作、时间和次数。手机可点击素材添加，也可拖入分组。优先级队列会展开主触发与额外触发，展示真正导出的检查顺序；执行指南可离线阅读完整规则。

详细入门、全部 14 个函数、优先级、执行记录与重试边界见 [JSON 战斗策略指南](docs/json-strategy-guide.md)。

多队伍操作与真实配队差异的依据见 [多队伍与共享角色](docs/multi-team-workflows.md)。队伍选择器切换当前编辑对象，旁边的管理按钮用于新建、导入和配置完整四人阵容；启用的队伍合并导出为一个 JSON。第四名成员即使没有动作，也参与阵容匹配。新建空队和复制的方案默认不参与导出。

共享角色的关联按钮列出各队分别配置的动作和条件，不会自动共用一套操作。合并时保留原生 `Index` 与额外优先级，按队伍隔离历史引用；主条件及所有 `MorePriorities` 都受完整阵容限制。同一实际四人可能匹配两个启用方案时，需要停用其中一个。原生只有一份开场动作与公共配置，冲突时可以明确沿用某队设置。TXT 每次只导出当前队伍。

## 多人联机

导入带 `Multiplayer` 的 JSON，或在 JSON 工程中打开工具栏的“联机玩家设置”。选择 2 至 4 名玩家和唯一房主，再按 `2/2`、`2/1/1` 或 `1/1/1/1` 配置各自能操作的角色。当前网站协作派发只支持双人；三人和四人可编辑、保存及导出，不会因此获得三人或四人任务派发能力。

时间轴分别展示各端角色，以及“各端通用”和“该玩家当前角色”动作。添加目标选择器决定新增动作归属；拖动已有片段或排序轨道不更改执行玩家。需要转移执行归属时，在片段属性中明确选择玩家和执行角色。同一角色可以属于不同玩家，同名动作和相同 `Index` 在各端独立保留。

私人动作的联动、换人间隔和释放锁定仅在本端计算，不会推走另一端或共用动作。共用动作仍加入每端检查；改变共用轨会影响各端。同一端的片段可框选移动，跨玩家的整组拖动会提示分别操作。

原生条件模式保留整个 `Actions` 的原始声明顺序、玩家归属、条件、优先级和扩展字段。步骤与计划模式按端独立编译；优先级队列也先绑定所选玩家，再展示本端及共用动作。这里只表示各端独立运行，没有共享毫秒时钟、队友技能读取或跨端成功确认。

每位玩家的开场指令与索敌选项分别保存；公共开场先执行，只能使用不指定角色的指令。已有 JSON 的 `EnsureCast` 与 `MorePriorities` 继续保留。选择玩家后可单独导出 TXT，导出前需确认丢失 JSON 条件调度；完整多人工程不会变为双方串行的 TXT。

多人玩家与“多套阵容”是不同功能。首版不允许把多人配置与 `teamPlans` 联合导出；带未分配兼容角色的旧工程需要先确定角色与归属。

角色和技能图片通过第三方公开图片地址加载；离线时显示文字图标，编辑、保存与导出仍可使用。软件不包含网站登录、扫码、云端项目或任务控制服务。

## 从源码运行

使用 Node.js 22.12 或更高版本：

```sh
npm ci
npm start
```

检查与测试：

```sh
npm run check
npm test
```

Windows x64 打包：

```sh
npm run dist:win
```

输出位于 `release/`。初版未进行代码签名。

预览分支的桌面窗口和解压后启动程序名为 `BetterGI Combat Editor Tree Preview`。构建时可用 `npm run dist:win -- --config.directories.output=release/0.6.0-preview.2` 将预览产物放入独立目录。

## 时间与执行

| 能力 | TXT 顺序命令 | JSON 条件策略 |
| --- | --- | --- |
| 调度 | 任务入口按命令顺序执行 | 每次动作后重新检查条件，选最小优先级的可用动作 |
| 战技衔接 | `skill`、`skill(wait)`、`skill(fast)` | `e-ready()`、`q-ready()`、条件不满足时等待或跳过 |
| 临场条件 | 不支持 JSON 条件表达式 | 低血量、爆发充能与就绪、前台角色、队伍成员、执行次数和历史时间 |
| 条件优先级 | 不支持 | 主优先级及 `MorePriorities` 替代触发条件 |
| 等待与键鼠 | 原生命令、独立普攻/等待/走位/冲刺、动作组 | 同一套原生命令 |
| 角色候选 | 可以包含多个角色，缺席角色由运行入口跳过 | 条件模式支持角色候选；步骤模式保留四个定位的兼容分支 |

新建 JSON 默认使用“条件与优先级”。可直接设置 `low-hp() && q-ready()` 等应急条件和优先级；时间轴的前后位置不替代原生优先级，也不强制生成固定轮转。导入创作者 JSON 保留其动作、条件、优先级、替代条件和扩展字段。

JSON 也保留“按步骤推进”和“按计划时刻”，适用于明确要编排步骤的场景。“按步骤推进”按动作命令结束记录和原生就绪条件生成依赖。命令结束不等于技能动画结束或释放成功：原生 `EnsureCast` 只提供 E 冷却检查与有限重试，重试耗尽仍可能继续；`ready` 等待操作界面恢复，不能当作通用成功确认。

条件 JSON 单独保存动作在原文件中的声明顺序。同优先级（包括 `MorePriorities`）的先后保持不变，参考轴拖动不会悄悄改写它；运行先后通过优先级和条件调整。TXT 与 JSON 步骤模式继续按排轴顺序导出。复制动作会获得独立索引。

导入原生条件 JSON 时，通用键鼠动作和状态标记使用独立轨道。超过四名角色的候选池按各角色最靠前的主优先级收纳，沿用原文件中禁用的空动作标题；分组按钮可切换查看角色或展开全部。显示分组不建立互斥关系，所有候选的原始动作、条件、额外触发和声明顺序继续参与导出。四名及以下角色逐人显示。

TXT 默认只导出命令顺序和显式等待，不将参考轴的空白或估算释放时间自动变成等待。可以开启“空隙导出为等待”；已校准的 E 释放等待也可单独开关。`round(1,3-5)` 限定轮次仅在支持轮次判断的一键战斗入口生效，普通自动战斗入口不保证执行该限制。TXT 的循环与战斗结束由 BetterGI 任务入口控制，界面的循环开关仅影响预览。

角色换人使用 1 秒间隔，开场无需额外等待；后台效果和冷却使用同一时间基准。释放动作和无动作站场分别显示。普攻、等待、移动等是可以独立排列的动作。

拖动可以将片段插入其他角色之前或之后。框选片段整体移动时保留内部间距，只吸附到前后相邻边界，并计入换人冷却。开启联动时推开冲突的后续片段；关闭时限制在能容纳所选组合的空隙里。如果组合内部的间隔无法满足新增的换人冷却，则保留原布局并提示调整间隔。

本仓库没有打包缺少明确再分发许可的第三方帧数表。未知释放时间会标为待实测；可在动作属性内设置校准值，校准会随工程保存。默认持续时间是规划估计，不能当作实测结果。

兼容角色以定位分支保存各角色的技能映射、参数和校准。JSON 步骤模式导出同一份原生策略供不同阵容选择；TXT 导出当前选中的分支，不伪装成运行时互斥分支。

## 工程兼容

工程格式保留 `betterbgi-combat-timeline`、版本 1，`strategyFormat: "txt" | "json"`；旧工程缺省为 JSON。切换格式保留另一模式的参数。多队伍以 `teamPlans`、`activeTeamId` 保存各队阵容和独立工程快照；顶层保留当前队伍，兼容现有网站 API。固定角色 JSON 流程使用编译器版本 3，兼容角色分支使用版本 4，多队伍联合导出使用版本 5，多人 JSON 使用版本 6。多人工程以 `multiplayer` 保存原生 `Version: 1` 配置、`clips[].playerId` 保存归属，`playerSettings` 保存每端参考循环；这些不会改变原生多人格式版本。JSON 策略保留工程元数据，重新导入时恢复队伍、玩家与排轴；手工修改外层原生 JSON 时以实际修改内容为准。TXT 按文本命令导入，精确排轴、两种模式设置和角色分支请用工程文件保存。

更改工程格式或导出语义时，需要保留旧版本迁移和往返测试。测试中的校准数据是人工构造的约束输入，不是实测帧数库。
